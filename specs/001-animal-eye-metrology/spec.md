# 功能規格書：動物眼睛量測 Pipeline（Image Segmentation + Metrology）

**Feature Branch**: `001-animal-eye-metrology`

**Created**: 2026-10-22

**Status**: Draft

**Input**: 使用者描述："讀取 PROJECT_PLAN.md，將圖像分割模型的輸出應用於實際測量學任務：從 COCO 資料集挑出含 2 隻以上動物的圖片，分割動物輪廓與動物眼睛，量測每隻動物的雙眼距離，以及任意兩隻動物的右眼距離，並說明所用模型、評估公式、量測方式與驗證方法。"

## Clarifications

### Session 2026-10-22

- Q: 當一張圖片中有 3 隻以上都成功定位右眼的動物時，測量 B（兩動物右眼距離）應該輸出哪些配對的距離？ → A: 以兩隻動物為標準情境（輸出該對）；當圖片恰出現 3 隻以上時，輸出所有已定位右眼動物的兩兩配對距離（C(n,2) 筆），以免遺漏。
- Q: 動物眼睛的定位應該以哪一種策略作為「主要」來源？ → A: 以頭部 mask + 幾何/暗區啟發式為主要來源，SAM2 point-prompt 精修為可選增強；所有以啟發式產生的眼睛座標一律標記為估計值。
- Q: 當啟發式無法可靠地找到某隻動物的眼睛時，系統應該如何處理該動物的雙眼距離量測？ → A: 將該動物標記為「無法量測」並記錄原因，不輸出臆測的距離值（量測誠實優先）。
- Q: 單張圖片「分割 + 眼睛定位」的處理時間，驗收時應以哪個環境與上限為準？ → A: 以 CPU 為參考環境，單張 P95 ≤ 5 秒，並記錄實測值（與 constitution 一致）。
- Q: 驗收與人工 ground truth 對照時，應以多少張 COCO 圖片作為評估樣本的最低數量？ → A: 至少 10 張合格圖片（含 ≥2 動物）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 量測單一動物的雙眼距離 (Priority: P1)

使用者提供一張含有兩隻（含）以上動物的圖片，系統自動辨識每隻動物、定位其左眼與右眼，並計算同一隻動物的左眼到右眼的距離，最後以疊圖與表格呈現結果。

**Why this priority**: 這是本題最核心的量測產出（測量 A），沒有它整個交付物就不成立。單獨完成此故事即可構成一個最小可用成果（MVP）：對至少一隻動物產出可驗證的雙眼距離。

**Independent Test**: 給定一張已知含動物的圖片，執行 pipeline 後，可在輸出表格看到每隻被偵測動物的左眼座標、右眼座標與雙眼像素距離，並在疊圖上看到左右眼標記與連線；不需要測量 B 即可驗證其價值。

**Acceptance Scenarios**:

1. **Given** 一張含兩隻貓的圖片，**When** 執行量測 pipeline，**Then** 每隻被成功定位眼睛的貓都會輸出一筆包含左眼 (x,y)、右眼 (x,y) 與雙眼距離的紀錄。
2. **Given** 某隻動物只能定位到一隻眼睛或完全無法定位眼睛，**When** 執行量測，**Then** 該動物的雙眼距離紀錄會被標記為「無法量測」並註明原因，且不會中斷其他動物的量測。
3. **Given** 一張成功量測的圖片，**When** 產出疊圖，**Then** 疊圖上可清楚區分左眼與右眼、顯示連線與距離數值。

---

### User Story 2 - 量測兩隻動物之間的右眼距離 (Priority: P2)

使用者希望得到「任意兩隻動物的右眼之間」的距離（測量 B），用以比較不同動物在影像中的相對位置關係。

**Why this priority**: 這是題目要求的第二項量測，價值僅次於雙眼距離；它依賴 User Story 1 已能定位右眼，因此排在 P2。

**Independent Test**: 給定一張至少含兩隻已成功定位右眼的動物圖片，執行後可在輸出看到以「動物 A 右眼 ↔ 動物 B 右眼」為一筆的距離紀錄。

**Acceptance Scenarios**:

1. **Given** 一張恰含兩隻且皆已定位右眼的動物圖片，**When** 執行量測，**Then** 系統輸出一筆該對動物的右眼對右眼距離紀錄。
2. **Given** 一張恰含 3 隻以上且皆已定位右眼的動物圖片，**When** 執行量測，**Then** 系統輸出所有兩兩配對（C(n,2) 筆）的右眼距離紀錄。
3. **Given** 圖片中只有一隻動物成功定位右眼，**When** 執行量測 B，**Then** 系統明確標示「不適用（需至少兩隻動物的右眼）」而非報錯。

---

### User Story 3 - 篩選合格圖片並產出可驗證的交付物 (Priority: P3)

使用者希望系統能從 COCO 資料集自動挑出「含 2 隻（含）以上動物」的圖片作為輸入，並輸出可供人工與量化驗證的交付物（疊圖、量測 CSV、評估報告）。

**Why this priority**: 這是讓整個流程可重現、可驗收的支撐性故事；資料篩選與交付物格式本身不是量測，但是交付與驗證的前提。

**Independent Test**: 對一個 COCO 子集執行篩選，可得到一份「含 ≥2 動物」的圖片清單，且對其中樣本能產出 `measurements.csv` 與疊圖，並能以人工標註對照計算誤差。

**Acceptance Scenarios**:

1. **Given** 一個 COCO 子集，**When** 執行篩選，**Then** 僅保留含兩隻（含）以上動物的圖片，並輸出可重現的篩選清單。
2. **Given** 已完成量測的一批圖片，**When** 匯出結果，**Then** 產生符合固定欄位結構的 `measurements.csv` 範例。
3. **Given** 少量人工標註的眼睛 ground truth，**When** 執行評估，**Then** 系統輸出以眼間距或頭框尺寸正規化的定位誤差（NME）與分割品質指標（IoU / Dice）。

---

### Edge Cases

- 圖片中動物彼此重疊或遮擋，導致 instance mask 相連或眼睛被遮住時，如何標示與處理？
- 動物側臉只露出一隻眼睛時，雙眼距離無法計算，應標記為不可量測並說明原因。
- 偵測到的動物信心分數過低時，其量測結果需被標記為低可信度。
- 同一張圖恰含 3 隻以上動物時，測量 B 輸出所有兩兩配對（C(n,2) 筆）；標準情境（兩隻動物）則為單一對。
- 完全沒有動物或只有一隻動物的圖片進入 pipeline 時，不應中斷批次，而是略過並記錄原因。
- 眼睛座標為估計（啟發式）而非模型關鍵點時，需在輸出中標記為估計值。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 能從 COCO 資料集（或其授權子集）篩選出「含兩隻（含）以上動物」的圖片，且篩選邏輯可重現。
- **FR-002**: 系統 MUST 對每張輸入圖片個別分割出每隻動物的輪廓（instance mask / bbox）與所屬類別。
- **FR-003**: 系統 MUST 對每隻被偵測的動物定位其左眼與右眼的像素座標。
- **FR-004**: 眼睛定位以頭部 mask + 幾何/暗區啟發式為主要來源（SAM2 精修為可選）；凡以啟發式產生的眼睛座標，系統 MUST 在輸出中標記為估計值。
- **FR-005**: 系統 MUST 計算每隻動物左眼到右眼的歐氏距離（測量 A）。
- **FR-006**: 系統 MUST 計算兩隻動物右眼之間的歐氏距離（測量 B）；標準情境為恰兩隻動物（輸出一對），當圖片恰含 3 隻以上已定位右眼的動物時，MUST 輸出所有兩兩配對（C(n,2) 筆）。
- **FR-007**: 當某隻動物僅能定位單眼、無法定位眼睛，或無法可靠定位眼睛時，系統 MUST 將其量測標記為「無法量測」並記錄原因，且 MUST NOT 輸出臆測的距離值；此情形不得中斷其他動物或其他圖片的處理。
- **FR-008**: 系統 MUST 輸出疊圖，於原圖上標示動物 mask、左右眼位置（可明確區分左右眼）、量測連線與距離數值。
- **FR-009**: 系統 MUST 輸出一份固定欄位結構的量測結果 CSV，至少包含：圖片 id、動物 instance id、動物類別、左眼 (x,y)、右眼 (x,y)、雙眼距離，以及（適用時）兩動物右眼距離與距離單位。
- **FR-010**: 系統 MUST 以單一宣告的座標慣例表示座標，並以單一宣告的單位表示距離（預設為像素；僅在提供比例尺時輸出實際單位）。
- **FR-011**: 系統 MUST 提供分割品質評估（IoU、Dice）與眼睛定位評估（以眼間距或頭框尺寸正規化的 NME）之計算能力。
- **FR-012**: 系統 MUST 提供人工標註對照的驗證方式，可對至少 10 張合格圖片的 ground truth 計算像素誤差 / NME。
- **FR-013**: 系統 MUST 對偵測信心分數過低的量測結果加以標記為低可信度。
- **FR-014**: 系統 MUST 在相同輸入與相同設定下產生相同的量測結果（可重現、決定性）。
- **FR-015**: 系統 MUST 對每張圖片的錯誤或空結果（無動物、僅一隻動物、未偵測到眼睛）產生清楚且可行動的訊息，而非裸露的錯誤堆疊。
- **FR-016**: 交付物 MUST 包含題目要求的項目：完整代碼、README、`.env.example`、至少一個量測 CSV 範例、系統架構圖；對不適用的項目（如 API 文件、測試帳號）MUST 於 README 明確標註「不適用」並說明原因。

### Key Entities *(include if feature involves data)*

- **輸入圖片 (Image)**：一張待分析的影像，具有唯一 id、尺寸，以及其中所含動物的數量（須 ≥2 才合格）。
- **動物實例 (Animal Instance)**：圖片中單一隻被偵測的動物，具有 instance id、類別、輪廓 mask、bbox、偵測信心分數，以及左眼與右眼座標。
- **眼睛座標 (Eye Point)**：某動物的一隻眼睛在影像上的像素位置，附帶「左/右」標記與「是否為估計值」旗標。
- **量測紀錄 (Measurement Record)**：一筆量測結果，可為「單一動物雙眼距離」或「兩動物右眼距離」，含相關實體參照、距離數值、單位與可信度/可量測狀態。
- **評估結果 (Evaluation Result)**：對分割或眼睛定位的品質度量，含指標名稱（IoU / Dice / NME）、數值與對照的 ground truth 來源。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 對一組合格（含 ≥2 動物）的測試圖片執行 pipeline，100% 的圖片都能完成處理（成功量測或以明確原因標記），不會因單張圖片失敗而中斷整批。
- **SC-002**: 對每隻「成功定位雙眼」的動物，系統都能產出一筆含左右眼座標與雙眼距離的紀錄，且疊圖上可被人工目視確認左右眼標記正確。
- **SC-003**: 對含至少兩隻已定位右眼動物的圖片，系統能正確產出兩動物右眼距離，且與人工在同一疊圖上量測的結果一致（方向與量級合理）。
- **SC-004**: 以至少 10 張合格圖片（含 ≥2 動物）之人工標註眼睛 ground truth 對照，系統能回報定位誤差（NME 或像素誤差）數值，作為定位品質的量化依據。
- **SC-005**: 在相同輸入與設定下重複執行兩次，量測數值完全一致（決定性可重現）。
- **SC-006**: 題目要求的交付物全部齊備：完整代碼、README（含專案介紹、技術棧、本地運行步驟、Docker 指令、API 文件與測試帳號之適用性說明）、`.env.example`、至少一個量測 CSV 範例、系統架構圖。
- **SC-007**: 單一圖片的分割加眼睛定位處理時間，以 CPU 為參考環境，P95 ≤ 5 秒，且須記錄實測數據（而非估計）以供驗收。

## Assumptions

- 動物類別任選，涵蓋 COCO 既有的動物類別（如貓、狗、馬、羊、牛、象、熊、斑馬、長頸鹿、鳥等）即可，不限定特定物種。
- 由於 COCO 不提供動物眼睛的標註，眼睛定位以「頭部 mask + 幾何/暗區啟發式」為主要來源，SAM2 point-prompt 精修為可選增強；所有以啟發式產生的座標一律標記為估計值。
- 距離預設以「像素」為單位；在沒有標定物（已知實際長度的參照物）時，不強制輸出實際世界單位，可改以像素距離或以眼間距正規化的相對距離表示並說明。
- 測量 B（兩動物右眼距離）的標準情境為「恰兩隻動物」，此時輸出該一對的距離；當圖片恰出現 3 隻以上已定位右眼的動物時，輸出所有兩兩配對（C(n,2) 筆）以免遺漏。符合篩選條件的圖片多數為兩隻動物，故多數情況為單一對。
- 參考硬體為 CPU，單張圖片「分割 + 眼睛定位」處理時間的驗收門檻為 P95 ≤ 5 秒，並於結果中記錄實測值；不預設評審具備 GPU。
- 本題以離線 pipeline 為主，無線上 API 服務與登入機制；README 中 API 文件與測試帳號將標註為「不適用」並說明原因。
- COCO 資料集與模型權重均於其授權範圍內使用，僅使用動物影像，不蒐集不必要的個人資料。
